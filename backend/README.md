# RECLAIM API

NestJS + Prisma + PostgreSQL. Google sign-in and backup/restore for the local-first app. Routes and rules: [docs/API_CONTRACT.md](../docs/API_CONTRACT.md).

## Run locally (no Docker needed)
```powershell
cd backend
npm ci
npm run db:local            # terminal 1: real PostgreSQL 17 in backend/.pgdata, prints DATABASE_URL
```
In a second terminal:
```powershell
cd backend
Copy-Item .env.example .env # then set DATABASE_URL to the printed one and a 32+ char JWT_SECRET
$env:DATABASE_URL = "<printed url>"
npm run db:migrate
npm run build
npm start                   # http://localhost:3000/v1/health, docs at /v1/docs
```
`main.ts` reads the process environment; load `.env` yourself (for example `node --env-file=.env dist/main.js`).

Google sign-in answers 503 until `GOOGLE_CLIENT_IDS` is set.

## Tests
```powershell
npm test
```
Starts its own throwaway PostgreSQL on a random port, applies the real migrations, runs the integration tests, then deletes it. Google is replaced by a fake verifier; everything else (tokens, database, validation, rate limits) is real.

## Schema changes
Edit `prisma/schema.prisma`, then `npm run db:migrate:dev -- --name <change>` against the local database. Commit the new folder under `prisma/migrations`. Production applies migrations with `npm run db:migrate` on start.

## Deploy (Neon + Render free tiers)
1. Neon: create a project and copy the **direct** connection string (the host without `-pooler`, with `sslmode=require`). Migrations need a direct connection, and one small server does not need the pooler.
2. Render: New > Blueprint, pick this repo; it reads `render.yaml`. Fill in `DATABASE_URL` and `GOOGLE_CLIENT_IDS`. `JWT_SECRET` is generated by Render.
3. Check `https://<service>.onrender.com/v1/health`.

The free Render service sleeps when idle; the first request after that takes about a minute. The app treats the server as optional, so this only delays a backup.

## Secrets
Never commit `.env`. Production secrets live only in the Render dashboard.
